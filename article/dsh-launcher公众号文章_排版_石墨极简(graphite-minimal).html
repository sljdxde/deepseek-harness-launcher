01

PAIN POINTS

在 macOS 上跑 Harness，为什么总感觉「差点意思」

如果你在 Mac 上用 DeepSeek Harness（简单说，就是那个跑在本地、帮你干活的 AI Agent 平台，内核叫 @deepseek-ai/dsh ）做开发，大概率踩过下面这些坑。说白了，不是不能用，是 用得不爽 。

命令行手敲，太原始

每次想开，都得在终端里敲一行 npx @deepseek-ai/dsh web ，然后自己盯着进程。终端一关，Harness 跟着没了；要是忘了关呢？后台悄悄躺着一堆 node、npm 进程，端口还被占着，下次启动直接冲突。

官方桌面版，太重了

官方那个桌面版是用 Tauri 打包的，里面塞了 WebView 外壳和一整套 Node 运行环境。功能是全，可对「只想在本地跑个 Harness」的 Mac 用户来说，它体量大、占内存、启动慢——你电脑上明明已经有 Node 了，它偏要再带一套。

没有菜单栏入口

想打开 Harness？翻终端、敲命令、等启动。没有全局快捷键，没有开机自启，也没有「就绪了自动帮你开浏览器」。它说到底只是个命令，不是一个 随时待命的工具 。

归档会话，难管

Harness 跑久了，归档列表越来越长。想清理？得自己去翻 session 目录、手动删文件、改配置文件——手一抖，索引就乱了。

插件生态，太散

社区里 awesome-dsh-plugin 有一堆好用的插件，可安装全靠手动跑命令。装了啥、什么版本、怎么卸，没有一个统一的地方能看。

更新，得自己盯

@deepseek-ai/dsh 发新版了，得自己刷 npm 才知道；启动器自己有没有更新，还得去 GitHub 看。没有自动检查，没有一键升级，纯靠记性。

最烦的：进程残留和端口冲突

关的时候直接 kill 进程？子进程可能漏杀。重启的时候旧进程没退干净？端口就被占了。这些「收尾」的脏活，本不该让人肉来做。


02

DESIGN CORE

做一层「恰到好处」的原生薄壳

Deepseek Harness Launcher（简称 DHL）的定位其实特别清楚：它想做 第三种、而且只属于 macOS 的轻量方案 ——在「命令行裸跑」和「官方重桌面版」之间，找一条最顺手的路。它的核心思路就一句话： 做个薄壳，只负责把门推开，不替你把家重新装修 。

纯原生，零包袱

整个启动器是用 Swift + AppKit 写的（AppKit 就是苹果自家的原生界面框架）。没有 WebView、没有 Electron、没有 Tauri——就是一份干净的原生 Mac 代码。它常驻在菜单栏，不在 Dock 占一格，跟着系统的浅色/深色外观自动切换，内存占用低到几乎可以忽略。

只做薄壳，不替代内核

这一点很关键：DHL 不自带 Node 运行环境，也不帮你管多个 dsh 内核版本 。它只干一件事——在你已经装好 Node 和 npm 的 Mac 上，把 @deepseek-ai/dsh 拉起来、管好、再顺手注入一点增强。你原来的 profile、会话、其他插件，全还是 dsh 自己管，DHL 绝不越界。类比一下：它像个懂分寸的管家，只帮你开门、开灯，不会擅自挪你家具。

安装省心，还省内存

第一次启动，DHL 会把 @deepseek-ai/dsh 装到 ~/.dsh/runtime 这个固定目录。它走的是 npm ci 这条「按清单精确安装」 的路子（不是那种每次瞎拉的 npm install），峰值内存只用到 0.3～0.6GB（CI 有 1GB 硬门禁兜底）。默认优先用国内镜像，失败再自动回退官方源。装好之后，后续启动直接复用这个固定 runtime，不再每次裸跑 npx 去重新解析，自然就快了。

智能端口，优雅退场

启动前，DHL 会扫一遍 3080 到 3099 这 20 个端口：发现已经有在跑、能响应的 Harness 实例，就直接复用；没有，就绑定第一个空着的端口。关的时候更讲究：它先发一个「温和的告别信号」（SIGTERM），给进程一点收尾时间，超时就升级成「强制终止」（SIGKILL），而且是 精确匹配自己的进程路径 才动手——不误杀别的程序，也不留孤儿进程。

注入增强，但不污染你的配置

DHL 不会改写你已有的 Cordis 配置文件。它启动时是 通过 --patch 方式注入自己的增强补丁 ，用软链接把内置的两个插件（归档管理、插件市场）挂进 dsh 的插件目录。将来你卸载 DHL，它只会摘掉自己那根链接，你的会话、profile、其他插件数据全都原样保留。


03

SOLUTION

每个痛点，都有一个对应的解

前面列的那些糟心事，DHL 基本是一对一对上了：

你遇到的麻烦 DHL 怎么解决
每次手敲命令启动 菜单栏图标常驻，点一下「打开」就走；用 Spotlight / Raycast 搜 dsh 或 dhl 也能秒开
想随时呼出 默认快捷键 ⌃⌥D，在任何应用里一键把浏览器跳到 Harness 界面；快捷键还能自己重新录制
进程残留 / 端口冲突 级联「先温柔后强制」终止 + 精确路径匹配，退出时清得干干净净
安装重 / 慢 / 易失败 固定 runtime + npm ci 低内存路径 + 镜像回退 + 实时进度条，看得见每一步
归档会话难管理 内置归档管理面板：列出归档、显示工作区和关联数量、支持单条或批量删除（带二次确认，防手滑）
插件分散难管理 内置插件市场：来自 awesome-dsh-plugin，能分类、搜索、按星级或下载量排序，一键装/卸
更新得自己盯 启动器自更新（对接 GitHub Releases，下载 DMG 自替换）；dsh 新版本也会异步检查并在菜单栏提醒你
没有开机自启 通过 LaunchAgent 实现登录自启，设置里一键开关
不知道运行没 菜单栏实时显示当前端口（没运行就显示「未运行」）；一键「打开日志」随时查

DEMO

它到底长什么样

先用大白话捋一遍整体架构，其实就三层： 菜单栏薄壳 → 拉起 dsh web → 浏览器打开界面 。也就是说，DHL 自己不画界面，它就是一个安静待在菜单栏的「启动器」；真正干活的还是你本地的 dsh；最后呈现给你的，是系统默认浏览器里的 Harness 网页界面。端口在 3080–3099 之间智能复用，没有补丁注入时也能降级跑基础模式。

待补素材

此处插入：新功能介绍 GIF

最后重点说说两个通过补丁注入的「新功能」——它们都不动你 Harness 原有的配置：

归档管理面板（DSHArchiveManager）

在 Harness 网页界面的侧边栏多了个入口，把你的所有归档会话列出来，连带着工作区、关联数量都标清楚。支持单选或全选、单条删除或批量删除，删之前有二次确认，防误删。

插件市场（DSHPluginManager）

侧边栏里「插件管理」入口，分「已安装」和「插件市场」两个页面。市场数据来自 awesome-dsh-plugin ，能分类浏览、能搜索、能按星级或下载量排序，看到喜欢的插件一键就装。装/卸都走 dsh plugin --profile web ，缺环境时还会自动帮你补齐。
