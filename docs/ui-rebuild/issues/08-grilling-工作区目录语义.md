## Question

「工作区只做组织层」已拍板，这一票把语义钉死到可写规格：

1. **工作区是不是宿主已有概念**（`sidebar.workspaces` 席位 / 宿主 workspace 服务）？是则复用宿主数据、不自造；否则壳自造的数据存哪、怎么持久化、怎么与宿主侧栏共存。
2. **会话绑定目录**：单选还是多选？绑定后影响哪些入口（顶栏面包屑 / composer 目录 pill / 新建流程），三处文案如何同源。
3. **与 FR-20 白名单、FR-35 权限范围的关系**：绑定目录不改变沙箱边界；绑定目录不在白名单内时，谁提示、提示什么。
4. **新建流程**：先选工作区→选目录，还是先建会话再绑？宿主已有空态时怎么不出现双空态。

产出：一段可直接进规格的语义定义 + 3 个边界场景的判定。

## Answer

（2026-11-20，人类回复「全部按照推荐」；C3/C4 已在原型 v4 落地。）

- **C1 数据来源**：优先复用宿主 workspace / 会话目录数据；宿主没有才本地持久化，并留迁移路径。
- **C2 绑定**：一个会话绑一个目录（单选）；面包屑、目录 pill、新建页三处同源现算，不各存一份。
- **C3 安全边界**：目录白名单仍是唯一沙箱边界；绑定目录不在白名单 → 允许绑，但打「需审批」标，首次执行触发审批。
- **C4 新建/删除**：保留「先选工作区 → 选目录 → 写第一句」；删除工作区时会话移到「未分组」，不静默丢。
- C1/C2 属规格层，进 09 收口；原型只体现 C3/C4。
