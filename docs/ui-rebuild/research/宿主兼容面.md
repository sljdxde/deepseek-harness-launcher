# 宿主兼容面与升级断裂点（研究 01）

来源：`compat-facts` 子代理，2026-11-20，全部证据取自本机实际安装文件。

## ① 扩展点

- slot/seat 只有一条入口：`ctx.slots.register / inject / provideRoot / entries`，由 `@deepseek-ai/dsh-client-ui-renderer` 承载（`docs/subsystems/slots.md:25`）。
- 类型包 `@deepseek-ai/dsh-client-ui-slots` **未随 runtime 安装**，第三方只做 type import，类型被擦除 → **槽契约没有运行时版本校验**（`dsh-package-manifest/src/types.ts:88-104`）。
- root 是内置单槽，`ui-renderer` 自己 `renderSlot('root')`（`registry.ts:375-393`）；d.ts 明写「DO NOT register here… it shadows」（`registry.ts:31-44`）——仍是内部实现注释。
- client entry：`package.json.dsh.client`，必须导出 `./client`，否则 boot 抛错（`dsh-client-modules/lib/index.js:792`）。
- bundle patch：`dsh.bundle.patch`；行 id `ui-layout` 在 `dsh-web-app/cordis.patch.yml:270-271`；patch 可按 id 覆盖非 `name` 字段，`disabled` 可覆盖（`cordis-plugin-include/src/patch.ts:11,63,97-98`）。
- 服务：`ctx.layout` 由 layout 包 `reflect.provide`，5 个宿主包 inject；`ctx.theme` 有公开注释；ILayout 无 `@internal`，但只在 README 内部段描述。

## ② 同名 drop-in 依赖的私有契约

- 包名+版本：`Plugins/DSHClientUILauncher/package.json:2-3` 冒充 layout@0.2.2-rc.5；runtime 实为 **rc.4**；baseline 记 rc.5（`contracts/host-baseline.json:4-6`）。
- 行 id：自己的 patch 是 `[]`，靠包名顶替 `ui-layout` 行。
- 六槽与 kind：`client/client.js:16-23` vs 宿主 `src/client/index.ts:192-205`，当前逐字一致。
- root renderSlots：`client.js:1684-1807` 逐个 `renderSlot`。
- ILayout 形状：`service.d.ts:24-50` 六成员；drop-in 自实现于 `client.js:2007-2025`（`beginNavigation` 返回永不 abort 的信号、`toggleSidebar` 空函数、`openRightbar` 丢 `fullscreen`）。
- 9 个 sidebar 席位：`host-baseline.json:48-94`，实际由 `ui-sidebar` 自己 register（`dsh-client-ui-sidebar/src/client/index.ts:93-104`）。
- 额外私有假设：`client.js:1325,1707` 读 `props.activeRail/status*`，框架根 props 只给 `useStore/useSessions/usePanelInfo/useFoldedLandscape/actions/renderSlot/t` → 恒 undefined。

**最可能断的 5 点**：①六槽集合/root 派生 props；②ILayout 面签名（5 消费者、无编译期检查）；③主题落地（宿主 ThemePresenter 随替换消失）；④版本锁（package/baseline/shell-switch 三处）；⑤入口与 bundle 语义（package.json 与 README 自相矛盾）。

## ③ 第三方 UI 插件挂法

- better-sidebar / dsh1024 / dsh-skins / dsh-clipchat **都不替换 root**，只 `slots.inject` seat 或 insert 行。
- 都靠 `dsh.bundle.patch` 被 `dsh plugin add` 自动加行。
- 公开路径只有「加法位」；`shell.overlay` 是整站浮层入口；root 明确禁止。
- 接管整站只能走 patch：disable `ui-layout` 行 + insert 自己的行，**不是 slot API 承诺**，现有第三方无人使用（profiles 下 `name: 'root'` 零命中）。

## ④ 冲突 / 降级机制

- `#launcher-conflict` **不是宿主机制**，是 drop-in 自己往 body 插的提示条（`client.js:1843-1853`）。
- 只有 `apply()` 内 provide/register 抛错才触发；单槽重复注册**不抛错**（优先级遮蔽），重复声明子槽才在 load 期抛。
- **不能做「升级后自动回原生」**：drop-in 顶替后宿主 AppFrame 已不在图里，root 无注册时 renderer 直接抛 `'root' has no registration`（`registry.ts:392-393`）。
- 真正回滚只有 profile 依赖层：`dsh plugin remove` + install + 重启。

## ⑤ 升级机制

- runtime 是独立 npm 项目（`@deepseek-ai/dsh: ^0.2.2-rc.4`）；启动器 `npm install` 升级会整棵替换 `runtime/node_modules`。
- profile 的 pnpm 解析优先于 installAnchor → 同名 drop-in 继续赢，宿主新版被遮蔽。
- 版本不匹配**不会拦**：只有 `engines.dsh` 或 `@deepseek-ai/dsh-*` peer 参与判定，且仅 warn + 可豁免；drop-in 两者都没有 → 静默加载。
- `package.json` 已声明 `dsh.bundle`，与 README / runbook 的「declares no dsh.bundle」不一致。
- 当前机器尚未安装该 drop-in。

## 最致命的 3 条风险

1. **版本冒充 + 零兼容声明**：宿主升级后 drop-in 仍静默赢，无报错、无提示；baseline 按 rc.5 冻结，实际验证的是 rc.4。
2. **独占 root + 6 槽硬编码**：宿主增删槽或改 kind，对应区域整块消失且控制台 0 报错。
3. **无运行时回退**：conflict 条不恢复原生，root 无注册即白屏；唯一退路是改 profile 依赖并重启。
