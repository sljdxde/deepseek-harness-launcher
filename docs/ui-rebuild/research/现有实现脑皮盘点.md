## 皮与融合版冲突的硬编码

1. 侧栏 280（原型 272，≤1080 降到 248）。
2. 右栏 380 / 320–520（原型 384，≤1240 340，≤1080 300）。
3. 断点 1020（右栏自隐）原型没有；原型 ≤980 侧栏+右栏一起转抽屉。
4. 860 抽屉断点原型没有（原型 980 抽屉、400 才降 rail）。
5. 容器查询 760/640/420 对不上原型的 700/560/400。
6. **缺 topbar，多 splitbar**：原型第一行是 46px topbar（标题/面包屑/右栏 chip），实现换成了分屏档位条。
7. statusbar 信息模型不同（原型等宽状态带 vs 实现三段文本 + 席位）。
8. B 方案（沿用宿主侧栏外观）与原型（全自绘侧栏）根本冲突。
9. `SidebarOwnerProps.collapsed` 读的 `props.sidebarCollapsed` 无人提供 → 恒 false。
10. `shell.leading` 塞进 rail 第一格（宿主是左上绝对定位），左上有两套东西叠着。
11. 一批自造 props 无供给方（status* / activeRail / selectedSessionId 等）→ 状态条、rail 高亮、空态判据退化。
12. 主题变量名写错（`--dsw-*` vs 宿主 `--dsh-*`）。
13. 宿主 ⌘B（`sidebar.left.toggle`）在换壳后是 dead control。
14. 宿主/原型/实现三套常量并存（264/272/280、384/380 等）。

## 重写最容易漏的 5 件事

1. 8 处逻辑靠人肉同步（`modelChipText`、`emptyStateDecision`、`assignPaneKeys`、`resolveSplit`、`nextEscapeTarget`、`collectCommands` 等），重写时要么生成要么内联。
2. **审批脑全、皮全缺**：`approvalRequest()` 未定义、审批卡只有 CSS、`OVERLAY_IDS` 无人注册。
3. 状态来源要重新定义，不能接着用无供给方的自造 props。
4. 契约快照有三处盲区：不取 owner props、不读 `SlotFactoryMap`、`openRightbar` 的 fullscreen / abort / `retainMainPanels` 未实现。
5. **验收现在就是红的**：本机 runtime 是 rc.4、baseline 是 rc.5，`contract-snapshot --check` 退出 3；`BUILD_STAMP` 落后 3 笔，`node --test` 202/203。
