# 兼容性改造方案（B 组，待签收）

> 依据：`research/宿主兼容面.md`（逐条 file:line 事实）。目标：**升级不白屏、坏了能回退、小版本零改动**。

## 0. 一句话

采用**混合形态 + 四道护栏**：平时只加公开扩展点；只有启动自检确认宿主契约没变，才用 patch 接管 root；任何时候都能一条命令回原生。

## 1. 形态：默认加法位，换壳走 patch

| 层 | 做法 | 依据 |
|---|---|---|
| 默认 | 只 `slots.inject` seat / 菜单行 / `shell.overlay`，不动 root | 第三方四个样本（better-sidebar、dsh1024、skins、clipchat）都这么挂 |
| 换壳 | `dsh.bundle.patch` disable `ui-layout` 行 + insert 自己的行 | root 在 d.ts 里写「DO NOT register」，整站接管不是 slot API 承诺 |
| 不做 | 直接 `register('root')` 抢注 | 会 shadow，且宿主升级后行为不可预期 |

## 2. 启动自检（Guard）：先检查，再注册

接管前逐项比对，**任一不符就不接管**：

- 宿主包版本（`@deepseek-ai/dsh`、layout、sidebar）是否在支持矩阵内；
- root 的 6 个子槽 `name / kind / scope`；
- `root.renderSlots` 集合；
- `ILayout` 六个成员是否齐全、签名可调用；
- 主题变量前缀（`--dsh-*`）是否还在。

不接管时：不注册 root、不抛错，显示一条可关闭的横幅「本版 UI 与当前 dsh 不匹配，已保留原生界面」+ 回退命令。

> 为什么必须「先检查」：单槽重复注册**不抛错**（只按优先级遮蔽），而 root 无注册时 renderer 直接抛错 → 白屏。宿主没有原生兜底。

## 3. 声明与版本

- `package.json` 增加 `engines.dsh` 与 `peerDependencies`（当前两者都没有，所以升级时**静默加载**）；
- 契约 baseline 用**实装版本 rc.4** 重新生成（现在记的是 rc.5，与实际不一致）；
- CI：对 rc.4 与最新 rc 各跑一次 `contract-snapshot --check` + 冒烟；
- 承诺：宿主 patch 零改动；minor 48 小时内跟进；major 走适配 + 回退窗口。

## 4. 回退（唯一不靠 UI 的保险）

- 入口：设置 → 高级 → 「回退原生 UI」；弹层里给出命令与 runbook；
- 动作：`dsh plugin remove @deepseek-ai/dsh-client-ui-layout` → `dsh plugin install` → 重启；
- 数据：审批策略与审计在 `~/.dsh/state/`，回退不丢；
- 验收：native → launcher → native 三态各一次，回退 3 分钟内完成。

## 5. 分发

| 通道 | 用途 |
|---|---|
| 随 DHL 安装包默认携带 | 普通用户零安装 |
| 独立 `dsh plugin add` | 开发/尝鲜/其它 launcher |

安装、升级、卸载三条路径都写进 runbook；升级前自动跑一次契约 check。

## 6. 风险与验收

| 风险 | 护栏 |
|---|---|
| 宿主增删槽 / 改 kind | 启动自检 + 契约快照 diff（CI 红） |
| ILayout 签名变化 | 自检逐成员探测；失败不接管 |
| 主题变量改名 | 自检前缀；不符只影响样式，不接管 |
| profile 解析顺序变化 | 安装/升级后跑 `check-installed-identity`（realpath + sha256） |
| 升级后白屏 | 不接管横幅 + 回退命令；CI canary 覆盖 rc.4 / 最新 rc |

**验收线**：契约 check 退出 0；升级 canary 不白屏；回退 3 分钟内完成；0 dead control（原型巡检）。
