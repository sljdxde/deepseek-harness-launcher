先说一个事实：当前实现里 99+ 永远不会出现

容量session.NewStore(50) —— 最多保留 50 条事件
裁剪超出 50 条时挤掉最旧的，并把被挤掉的会话从未读里一并删掉
结论未读上限 = 50，角标最多显示 50；99+ 目前是死代码（mac 版同样）
要真正支持 99+，需改两处：
① 把 store 容量从 50 提到 200（内存开销很小，每条只是一个短结构体）；
② 角标超过 99 才显示 99+（现有 BadgeText 已经这么写，改容量即生效）。
我的建议：方案 1 + 容量提到 200。 与 mac 口径一致（mac 也只列最近 6 条）；浮层高度固定，不会因未读多而撑爆屏幕； 「还有 N 条」明确告知总量；真要逐条处理，用户会去 Harness 里看。
