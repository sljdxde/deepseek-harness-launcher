v2 · SVG 图标 / 内置·发现·已安装 / 推荐位+双榜+分类 / 多仓库源 原型固定浅色 · 落地后主题跟随 dsh 设置
三个方案共享的设计决定（差异在信息架构，不在组件）：
  • 图标：全部 SVG 线性图标（16 网格 / 1.5 描边 / currentColor），插件 logo 位用「分类着色的图标块」，真实落地时若有插件自带 logo 则替换之。
  • 三大视图分开：内置（系统自带，只有开关）/ 发现（市场）/ 已安装（管理）。入口形式三案不同：A 顶部导航行、B 左栏、C 页签。
  • 发现页结构：今日推荐位 + 下载最多榜 + 星标最多榜 + 分类 chips（带数量）+ 分类分区卡片 + 底部 sticky 手动安装行。
  • 插件源管理（新增）：预设源（官方索引 / 社区精选 / awesome 合集 / npm 标签聚合）点选开关即加，也可粘贴 github:owner/repo 或索引 JSON 地址自定义添加；每个源显示插件数、上次同步时间、可停用/删除。索引格式约定 index.json，服务端聚合去重。
  • 榜单口径：下载最多 = 各源 index.json 的 downloads 聚合（npm 上周数据可选）；星标最多 = GitHub stars。落选理由不需要：榜只取前 5。

方案 A · 市场大厅 magpie 最新版同构 · 最重

与 magpie 最新发现页逐区对应：面包屑顶栏（下载加速开关 + 搜索 + 更新按钮）、内置/发现/已安装导航行、本周标题、今日推荐大卡 + 右侧下载榜、分类 chips + 来源/排序下拉、分区卡片栅格、sticky 手动安装行。源管理从「来源 ▾」进入弹层。

三案对比

A 市场大厅：结构与你给的最新 magpie 截图一一对应，推荐位最大、浏览感最强；源管理藏在 gear/来源下拉里，是弹层。适合「插件页 = 商店」的定位。
B 左栏工作台：源管理是一等页面，双列把「逛」与「查榜」分开；左栏四项在窄窗口（dsh 内容区 < 900px）会退化为顶部一行。适合重度管理场景。
C 紧凑仪表盘：一屏信息最多、滚动最少，表格行扫得快；但推荐位被压缩，"逛"的氛围最弱。源管理是轻弹层。

共同的新数据需求（落地时服务端配合）：index.json 索引格式（name/repo/url/description/categories/stars/downloads/verified）+ 多源聚合去重 + 源配置存 profile。UI 三案都只需现有 install 接口 + 新的 sources 管理接口（GET/POST/DELETE）。
