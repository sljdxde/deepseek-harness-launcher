任务栏未读交互 · 两套方案

方案 A推荐

点任务栏图标 → 图标正上方弹出未读列表。点其中一条 → 浏览器打开并跳到该会话。最接近 mac 菜单栏的体验。

实现方式

触发点击任务栏按钮（不是右键）→ 弹出浮层
定位用 SHAppBarMessage(ABM_GETTASKBARPOS) 拿到任务栏位置，浮层贴在图标正上方
内容未读会话列表（时间 · 工作区名 · 结果），最多 6 条
点击条目打开浏览器 → 选中已有标签 → POST /dsh-session-notify/open 切会话 → 清该条未读
关闭点浮层外 / Esc / 再次点图标
优点：与 mac 菜单栏几乎一致——点图标看列表、点条目跳会话。 文字能完整显示工作区名与结果，条目数不受限（可滚动）。
难点：需要自己做一个无边框浮层窗口，并处理「点外部关闭」「跟随任务栏位置/自动隐藏」。 这是 Windows 上 唯一 能做到「点图标弹出带文字的列表」的方式——系统原生 API 给不了。

方案 B

用 Windows 原生缩略图工具栏：悬停图标时，缩略图上方出现一排小按钮。系统原生、代码少，但只能放图标和极短标签。

实现方式

触发鼠标悬停任务栏图标 → 系统显示缩略图 + 工具栏
APIITaskbarList3::ThumbBarAddButtons / ThumbBarUpdateButtons
限制最多 7 个按钮；按钮只能放 16×16 图标 + 极短 tooltip，不能放文字列表
点击收到 WM_COMMAND → 打开浏览器并跳会话
优点：纯系统原生，行为符合 Windows 习惯；不用自己做浮层窗口，代码量小得多； 任务栏缩略图是 Explorer 管理的，位置永远正确。
缺点：只能显示图标按钮，看不到工作区名字与时间； 最多 7 个（未读超过 7 个要分页或只显示前几个）； 必须悬停才出现，不像点击那样直观。

两套方案的关键差别

发现方式A：点图标；B：悬停图标
能显示什么A：时间 + 工作区名 + 结果（完整）；B：只有图标 + 极短 tooltip
条目上限A：不限（可滚动）；B：7 个
实现成本A：中（自绘浮层 + 定位 + 失焦关闭）；B：低（原生 API）
与 mac 相似度A：高（点图标看列表）；B：中（悬停看图标按钮）
我的建议：方案 A。你的目标是「和 mac 一样的效果」——mac 的菜单栏点下去就是一个带文字的列表， 点某一条直接跳会话。方案 B 做不到这一点（只能图标按钮），而且未读多时会被截断。 A 的实现成本高一些，但换来的是完全对等的体验。
